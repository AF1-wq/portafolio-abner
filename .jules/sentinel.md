## 2026-10-25 - Fix CSRF Vulnerability via Simple Form Submission
**Vulnerability:** The `/api/send-message` endpoint used a fallback `request.form.to_dict()` logic for non-JSON requests. Since this endpoint strictly processes and forwards emails from user input (changing server state or external systems), this fallback effectively bypassed CORS preflight checks, allowing attackers to exploit simple cross-origin form POST submissions to launch Cross-Site Request Forgery (CSRF) attacks.
**Learning:** Accepting `application/x-www-form-urlencoded` or `multipart/form-data` on API endpoints meant for JSON opens up the endpoint to CSRF from any domain, since browsers do not enforce CORS pre-flights for simple requests. Even with CORS configured, simple requests are still sent, and their side-effects might be triggered.
**Prevention:** Explicitly enforce the `application/json` Content-Type using `if not request.is_json:` check and reject non-JSON payloads with a `415 Unsupported Media Type` status, ensuring that browsers execute CORS pre-flights (OPTIONS) before sending the POST request with the JSON payload.
