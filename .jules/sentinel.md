## 2026-10-12 - [CSRF Mitigation on Public Unauthenticated Endpoints]
**Vulnerability:** The `/api/send-message` endpoint accepted POST requests via both JSON and `application/x-www-form-urlencoded`. Because there was no CSRF token or session validation (since it's a public contact form), attackers could host a malicious site with a standard HTML form that automatically submits to this endpoint. This allows them to bypass the application's rate limiter (which tracks IP addresses) by forcing innocent victims' browsers to perform the request, effectively using victims as a botnet to spam the endpoint or exhaust the daily email quota.
**Learning:** Even unauthenticated POST endpoints need CSRF protection if they consume resources or perform actions.
**Prevention:** We enforced `Content-Type: application/json` and removed the form-urlencoded fallback. Browsers prohibit cross-origin `application/json` POST requests without first sending a CORS preflight (`OPTIONS`) request. Since the server does not return permissive CORS headers, the browser blocks the request entirely. This simple check provides robust protection against traditional form-based CSRF attacks on API endpoints.
